# AlphaMill Console — UI 交互设计稿说明

配套文件：[`index.html`](./index.html) + [`styles.css`](./styles.css) + [`app.js`](./app.js)。
浏览器直接打开 `index.html` 即可评审，支持 `#factors`、`#detail`、`#strategy` 等 hash 深链直达单页。

## 定位

- 这是 **终局自建版**设计稿：按 ADR-0005 的自建前端路线绘制，不代表 Grafana/FreqUI 过渡形态；
- 开发可后置（F005 立项后实施），但信息架构与数据契约以本稿为准；
- **全部数字为占位假数据**，仅用于传达布局与信息密度，不表征任何真实回测/运营结果；
- UI 内不承载设计元注释，全部说明集中在本文档（设计稿即最终交付形态）。

## 设计方向：简洁高效

- 浅色中性底（`#f6f7f8`）+ 白色卡片 + 细边框，无渐变、无重阴影、无装饰性纹理；
- **单强调色**（蓝 `#2563eb`）用于导航选中、主按钮、图表主线；语义色只保留两类：
  绿 `#15803d`/红 `#dc2626` 表示收益正负，琥珀 `#b45309` 表示告警/降级状态；
- 中文界面字体走系统 sans，数字一律 `tabular-nums`，代码类取值（factor_id、版本号、路径）用等宽字体；
- 8px 圆角、轻阴影、克制的留白；信息密度优先于视觉表演。

## 信息架构 × 交付阶段 × 数据契约

> 每行即未来实现时的一个（组）API 端点；所有端点由 `src/alphamill/api/`（ADR-0005 统一只读后端）提供。
> 因子详情与因子对比是因子库的**二级页**，不入左树。一级视图共 4 个：
> 策略运营（落地页）/ 因子工厂 / 因子库 / 设置。

| 视图 | 层级 | 阶段 | 对应需求 | 数据来源（端点 → 视图/真相源） |
|---|---|---|---|---|
| 因子工厂 | 一级 | F005 | FR2 / FR3.3 / FR8.1 | `GET /api/v1/factory` → `v_funnel_status`（experiment_store 投影） |
| 因子库 | 一级 | F005 | FR8.1 | `GET /api/v1/factors` → `v_factor_metrics` 投影表 |
| 因子详情（含生命周期工作流） | 二级 | F005 | FR8.1 / FR7.1 / FR3 | `GET /api/v1/factors/{id}` → 报告文件 + manifest 直出；工作流各环节状态取自 experiment_store 台账 |
| 因子对比 | 二级 | F005 | FR8.1 | `GET /api/v1/factors/compare?ids=` → 同窗口同 data_version 对齐 |
| 策略运营 | 一级 | M3/M4（现阶段 Grafana 板 2 + FreqUI 承载） | FR8.2 / FR5.6 / FR6.1 | `GET /api/v1/ops/*` → 运营视图（TSDB 口径单点）+ Freqtrade REST 代理（持仓/平仓/每日收益）；信号源健康并入状态带与滚动 IC 卡 |
| 设置（Tab1 业务配置 / Tab2 项目运维） | 一级 | F006（看板部分 F005 起） | FR8.3 / FR8.4 / FR7.4 | Tab 切换在白板外；Tab2 拆两块板：服务健康 `GET /api/v1/settings/services`（行内操作即时生效）与日志记录 `GET /api/v1/logs`（append-only 唯一时间线） |

## 关键设计决策记录

- **首屏命名「工作台」**：定位是个人工作台（今天需要关注什么），不是系统总览；
- **生命周期模型 = 7 个宏观阶段**：生成 → 评测（含纯度/成本/查重子门）→ 选择期 →
  组合 → 验证（留出 90 天 + 最终确认）→ 上线（部署复核 + 挂载）→ 监控。对齐 PRD FR3.4
  的验证顺序，不把子门禁升格为阶段；
- **详情页工作流为单主轴鱼骨图**：7 个阶段节点上下交错，节点四态——✓ 通过（绿）/
  ● 进行中（蓝）/ ✕ 拒绝（红，流程终止）/ · 未到达（灰）；被毙的具体子门（如「成本否定」）
  写在节点信息里；自「验证」起为组合级环节（PortfolioDef 整体进行）；
- **因子库以「生命周期进展」列替换「结论」列**：7 节点迷你进展点阵（同鱼骨图配色），
  悬停显示阶段名与状态，全流程状态先于文字结论被感知；结论详情进二级页查看；
- **因子对比不入左树**：因子库勾选 ≥2 项后「对比」按钮点亮进入；
- **原「实验漏斗」更名「因子工厂」并通俗化**：四张卡讲流水线故事（本周产出 → 初筛存活 →
  组合验证中 → 在跑与监控），流水线分布与批次表全中文化（晋级/淘汰/成本否定），
  有效独立数等研究指标作为辅助信息收纳；
- **运营合并为一个页面**：策略运营 = FreqUI 的单笔交易视角（当前持仓、近期平仓）
  + 整体策略视角（统计卡、累计曲线）；信号源健康以状态带 + 「信号预测力（7 天 IC）」卡
  并入（卡片内用一句话解释 IC 含义与降权阈值），不设独立信号页；
- **平台观测与操作合并为「设置」**，三个分区以小标题分隔：
  - *服务健康*：可操作的服务矩阵（freqtrade 启停与强制单、Kronos/采集器重启、快照手动触发、
    门禁立即运行），原平台健康指标折算为各行关键指标；控制台自身后端不是矩阵成员
    （它是本页面的实现，不是被管理的服务）；
  - *业务参数*：真正的业务设置——交易风控（亏损/回撤熔断、相关性护栏、仓位上限）、
    验证门禁（留出窗、每周晋级上限、样本量阈值、IC 降权线）、成本模型（taker/滑点/资金费）、
    信号执行（陈旧度上限、实盘开关）、组合工厂（Top-K、换手预算）。每次修改生成新规则
    版本（rv-n）并自动记入日志（FR7.4）；实盘开关默认关闭，开启需最终确认 + 可信样本量；
  - *日志记录*：唯一时间线，类型可筛选（操作/审批/生命周期/人审/参数/系统事件）；
  因子/组合的生命周期动作（降权/暂停/下线）属于对象上下文，放在因子详情页而非设置页；
- **左树 4 项（总览 / 监控 / 因子 / 设置），带图标，可收起为纯图标栏**：「因子」页 =
  因子工厂总览（上半）+ 因子库列表（下半）合并，产出到列表同页动线最短；落地页 = 总览；
- **总览 = 全工作流闭环的实时呈现**：动画流水线（粒子流动 + 站点存量 + 落站脉冲）+
  证据库托盘（评测/选择期/组合/验证/监控的淘汰粒子均落入——对齐架构生命周期图
  「所有拒绝点进证据库 X」）+ 紫色反馈弧（证据库 → 归因复盘 → 新假设入队 → 回到生成，
  FR6.3-6.5 闭环；验证阶段的留出 FAIL / UNDERPOWERED / 最终确认 FAIL 同样是复盘输入），
  下方三卡（策略执行 / 信号与数据 / 昨夜产出）；不含任何待办类内容；
  鱼骨图仅保留在因子详情页（单因子旅程语义，聚合视角用流水线动画）；
- **移除「工作台/总览」页，落地页 = 策略运营**：管线核心是全自动闭环，界面不出现
  「待你处理」的待办与提醒；人的查阅需求由「设置 → 日志记录」（业务记录唯一时间线）满足。
  注意与 PRD 的张力：FR5.2 部署前复核与 FR6.4/6.5 人审入队仍是流程要求，本稿只是不再把
  它们做成待办界面——它们作为已发生的记录出现在日志中；若要彻底取消人审环节，属 PRD 变更；
- **服务矩阵只列长驻服务**（freqtrade / kronos-signal / data-collector / timescaledb / grafana）；
  快照导出是每日 02:00 的计划任务而非长驻服务，其完成状态由日志记录承载，不入矩阵；
  控制台自身后端同理不是矩阵成员；
- **设置页 tab 化**：业务配置（业务参数表）与项目运维（服务健康 + 日志记录）分属不同维度，
  tab 分开；小标题与表格同处一张白板。

## FR8 红线在设计稿中的落点

- **FR8.1**：研究视图（漏斗/因子库/详情/对比/谱系）只渲染版本态产物，每个数字可追溯
  manifest（data_version / cost_model_version 在顶栏与详情页可见）；实时运营数据不进入研究视图；
- **FR8.2**：同一读数在 Grafana 与本控制台同源（运营视图），并存期对数 diff=0；
- **FR8.3**：应急操作/生命周期动作是全站唯一写入口，均需二次确认并记入审计台账；
- **FR8.4**：门禁与统计裁决不出现在任何可点击路径上——「验证结果」面板只读呈现最近一次
  `python3 tools/verify.py` 的结果。

## 交互说明

- 左侧导航切换视图；`data-goto` 的「查看全部 →」跳转对应视图；
- 因子库：结论/生成器/数据版本三维过滤 + 文本搜索；点击行进入详情；勾选「对比」列加入
  对比视图（上限 4 条）；
- 因子对比：chips 增删叠加因子，指标表自动高亮每行最优值；
- 所有详情曲线由因子 id 作种子的确定性伪随机游走生成（mulberry32），同 id 每次打开图形一致，
  便于评审对照。

## 演进

- F005 立项时：本稿作为 spec 的 UI 附录，视图清单直接映射端点清单；
- 深色偏好若回归：设计 token 全部集中在 `styles.css` `:root`，可派生暗色主题而不动结构；

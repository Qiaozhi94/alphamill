# AlphaMill — 产品需求文档（PRD）

> 版本：v0.1 | 日期：2026-09-13 | 状态：草案

## 一、背景与问题定义

### 1.1 quant-crypto 复盘

上一代项目 quant-crypto 已建成可复用的数据、推理、执行、风控与监控基础设施：631 万行
1m OHLCV、衍生品特征、Kronos 信号缓存、Freqtrade dry-run、风险保护、90 天留出门和信号
质量监控。最终状态为 `blocked_no_paper_candidate`：所有候选均未通过最终留出。

这次失败暴露的不是单点工具缺失，而是研究到交易之间没有形成可持续运转的闭环：

- 假设主要靠人工提出，5 周只覆盖 3 个信号族，探索速度慢；
- 因子生成、成本评估、统计验证与策略构建的优化目标不完全一致；
- 数据、实验、信号和交易结果之间缺少统一谱系，复现与重定价成本高；
- 失败结果没有结构化回流为下一轮假设，研究循环无法积累；
- 研究 PASS、组合纳入、部署和线上衰减之间缺少完整生命周期管理。

AlphaMill 要解决的不是“多生成一些公式”，而是把 **Alpha 的发现、证伪、部署和运营**
做成一条可信、可复现、可持续学习的生产管线。

### 1.2 项目决策

1. **以 AI 因子工厂为核心引擎**：程序化、RL、人工与 LLM 共同生产带来源和经济假设的
   因子定义；AI 负责探索和复盘，不负责放宽证据标准。
2. **以端到端闭环为产品边界**：数据治理 → 假设与因子 → 评测与验证 → 组合与策略 →
   执行 → 监控归因 → 新假设，任一环缺失都不算系统完成。
3. **规则约束证据，确定性系统负责执行**：成本计算、无前视审计、统计门禁、风险约束和
   下单路径保持可测试、可审计，不交给非确定性 Agent 裁决。
4. **复用成熟基础设施**：quant-crypto 资产一次性清算迁入；Freqtrade 继续承担执行；
   Vibe-Trading 等外部工具只作为可替换的第二实现或 Agent 能力提供者，不成为主链路依赖。

## 二、产品定位、边界与成功定义

### 2.1 一句话定位

> AlphaMill（中文别名：淘沙）是一套 **AI 原生的加密量化研究与交易管线**：以 AI 因子工厂
> 为核心，将数据治理、假设生成、因子评测、严格验证、组合构建、交易执行与绩效复盘连接成
> 可复现的闭环，持续发现并运营成本后有效的 Alpha。

“每周候选数”是工厂产能指标，不是产品目的。系统成功取决于能否持续把有效独立的研究假设
转化为可信、可部署、对组合有增量价值并能被线上反馈管理的交易能力。

### 2.2 产品原则

1. **证据优先于产量**：提高吞吐量不得降低统计门槛、成本标准或无前视要求。
2. **闭环优先于局部最优**：不能进入组合、部署和复盘的因子，不是完整产品产出。
3. **独立性优先于名义数量**：以 OOS PnL 相关性聚类后的有效独立候选衡量探索广度。
4. **成本后结果优先**：交易费、滑点和资金费率是选择回路的一部分，不是事后报告。
5. **组合贡献优先于单因子排名**：候选最终按对现有组合的边际收益与风险贡献判断价值。
6. **失败也是资产**：失败必须有可查询的证据、归因和后续动作，但失败本身不等于成功。
7. **适应性是系统属性**：市场状态只用于条件化诊断和预注册风险动作；系统靠可复现重评、
   生命周期管理和新假设回流适应变化，不靠增加北极星指标或事后改规则证明“适应”。

### 2.3 指标体系

| 层级 | 指标 | 口径 |
|---|---|---|
| 北极星结果 | **可信 Alpha 产出** | 滚动 28 天内新增的有效独立 `PortfolioDef` 数；须在选择期构建并冻结，成本后为正、通过无前视与最终确认、达到可信样本量（约 ≥69 笔）、部署前复核有效，且对现有组合有正边际贡献 |
| 转化效率 | 研究到证据周期 | 假设注册至得到 `promising / dead / underpowered` 可审计结论的中位时间 |
| 转化效率 | 证据到部署周期 | 最终确认通过至可挂载 dry-run ≤1 天 |
| 探索能力 | 有效独立假设吞吐量 | 每周名义候选数及选择期 purged CV 的 OOS PnL 聚类后有效独立数并列；名义目标 ≥100/周，不单独作为成功判据 |
| 漏斗健康 | 分级转化率 | 生成 → 纯度门 → 因子证据/成本门 → 去重/多重检验 → 选择期 → 组合门（冻结 PortfolioDef）→ 留出门（含样本量三级裁决）→ 最终确认 → 部署前复核 |
| 线上结果 | 组合运行质量 | paper/live 的成本后收益、回撤、容量、回测偏差与因子衰减；按策略预注册基准判断，不设跨策略统一收益承诺 |
| 信任护栏 | 数据与实验完整性 | 有效数据快照、实验 manifest、留出使用台账、可复现率均为 100%；前视泄漏容忍度为 0 |

北极星指标允许在早期长期为零。为避免用“平台仍在建设”无限解释零产出，必须执行 §2.6 的
预注册论题检查点；工程里程碑用正控制验证管线能力，不拿正控制冒充新 Alpha。

### 2.4 产品目标

| ID | 目标 | v0.1 验收 |
|---|---|---|
| G1 | 建立端到端可运行闭环 | 至少一个正控制或历史候选完成：数据快照 → 因子注册 → 评测/门禁 → 组合 → dry-run/paper → 监控归因 → 生成后续假设；全程有机器可追踪证据 |
| G2 | 建立可信 Alpha 转化机制 | 所有新增候选按 §2.3 北极星口径统一裁决；30~69 笔只可临时 PASS，不能计入可信 Alpha |
| G3 | 建立 AI 因子工厂 | 至少两类可插拔生成器；稳定达到 ≥100 名义候选/周，并同时报告有效独立数、来源分布和各级漏斗 |
| G4 | 保证研究证据可信 | 100% 候选遵守选择期、留出预算、永久隔离最终确认窗、无前视三层审计、成本三档与多重检验控制 |
| G5 | 打通策略化与执行 | 单因子和 meta-factor 均可进入组合构建；最终确认通过至 dry-run ≤1 天；执行结果可回流至同一生命周期对象 |
| G6 | 全链路可复现、可运营 | 数据、代码、参数、随机种子、成本模型、窗口、组合权重、信号和交易结果有统一谱系；历史实验可从 manifest 重建 |
| G7 | 研究论题有停止时钟 | M4 启动 10 周或累计 100 个有效独立候选进入评测时触发 §2.6，先到为准，不允许默认续期 |

### 2.5 范围与非目标

**v0.1 范围**：OKX USDT 永续 30~50 对、1h/4h 为主；覆盖数据治理、研究、验证、组合、
dry-run/paper 执行、监控与复盘。实盘接口和风控路径可以保留，但只有满足 ADR-0003 的纪律后
才能启用。

**非目标**：

- 不自研交易所连接器、通用回测引擎或监控平台；
- 不替换 Freqtrade，不使用 Vibe-Trading 的实盘栈；
- 不让 Agent 直接修改门禁、审批上线或触发真实下单；
- 不以覆盖全部交易所、全部品种或高频交易为 v0.1 目标；
- 不因缺少存活候选而降低留出、样本量、成本或无前视标准。

### 2.6 论题检查点

触发器为 M4 启动后满 10 周，或累计 100 个有效独立候选进入评测，先到为准。有效独立性按
全部被评估表达式在选择期 purged CV 中的 OOS PnL 相关性聚类测量，不读取最终留出或永久确认
数据，也不能用名义候选数或存活者数替代。

触发时跨多个留出窗复核，并执行一个预注册分支：

1. **成本主导流失**：成本门是最大流失级，转向低换手、maker 优先、延长持有期等成本 pivot；
2. **假设源枯竭**：IC/收益证据近零且候选高度相关，转向新数据、新经济假设与种子来源；
3. **有可信存活**：至少 2 个候选达到 §2.3 北极星的候选级口径，结合组合贡献和漏斗改善
   书面决定是否继续；不得默认续期。

同期运行 funding carry 与 BTC/ETH 截面动量两个 crypto 原生正控制。正控制失败表示数据、
成本模型或评测台需要修复，不能据此判定研究论题失败；正控制通过也不能计入可信 Alpha 产出。

## 三、用户与端到端场景

用户是项目所有者，同时承担研究员、策略工程师和交易运营者角色。

| ID | 场景 | 期望结果 |
|---|---|---|
| S1 | 建立可研究数据版本 | 从联机库生成通过质量门、带完整谱系的不可变 Parquet 快照 |
| S2 | 批量探索假设与因子 | AI/RL/GP/人工来源生成带经济解释、数据依赖和代次标签的 FactorDef |
| S3 | 自动证伪与晋级 | 因子经成本、去重、多重检验与选择期分诊；组合门冻结 PortfolioDef 后经留出（含样本量三级裁决）与最终确认晋级 |
| S4 | 构建可交易策略 | 把单因子或协同池 meta-factor 映射为满足权重、换手、敞口和冲突约束的组合信号 |
| S5 | 安全部署与运行 | 同一版本化信号经部署前复核后进入 Freqtrade dry-run/paper，风险保护持续生效 |
| S6 | 监控、归因与复盘 | 对数据、信号、成交、成本偏差、组合绩效和衰减统一观测，异常触发降权、下线或复盘 |
| S7 | 让反馈产生下一轮实验 | Agent 读取不含永久确认窗信息的 manifest 和报告，提出人审后的新假设并重新进入同一管线 |
| S8 | 以统一界面审查研究证据与运营状态 | 版本化报告、收益曲线、实验谱系和运营指标经统一只读界面浏览；人审与生命周期动作经带审计的入口完成 |

## 四、功能需求

### FR1 数据治理与研究快照

- **FR1.1 联机采集**：TimescaleDB 承担流式采集、幂等修订、连续聚合、质量标记和运营查询。
- **FR1.2 不可变快照**：data_bridge 将 OHLCV、funding、basis、OI、Kronos 信号与必要日志导出为
  分区 Parquet；每次导出生成含来源、时间、口径、行数、质量状态和 `data_version` 的 manifest。
- **FR1.3 研究只读边界**：挖掘、评测和回测只通过 DuckDB 读取有效 Parquet 快照，不直读修订态
  TimescaleDB；失效快照必须被下游拒绝。
- **FR1.4 双口径与时间语义**：`close_adjusted` 用于收益，`close_raw` 用于成交模拟；所有时间使用
  UTC，并维护湖内 pair、研究 symbol 与 Freqtrade pair 的显式映射。
- **FR1.5 数据质量与扩容**：宇宙扩至 30~50 对前完成缺失、重复、未闭合 K 线和跨周期对账，
  保存 point-in-time 宇宙成员关系以避免幸存者偏差。历史回填约 4600 万行，是项目所有者负责的
  独立工作流，预计 1~2 周 wall-clock。
- **FR1.6 灾备**：数据库、Parquet manifest 与实验报告每日备份至 NAS，本地保留滚动副本并定期恢复演练。

### FR2 AI 因子工厂

- **FR2.1 假设注册**：记录经济动机、作用机制、数据依赖、适用状态、持有期、成本敏感性、来源与
  generation；只有表达式没有假设的自动候选必须标记 `mechanism_unknown`。
- **FR2.2 可插拔生成器**：至少包含 AlphaGen RL 主引擎与 GP/表达式或人工/LLM 中的一种独立后端。
  生成器只产出 FactorDef/协同池定义，不拥有最终评测权。
- **FR2.3 目标对齐**：奖励或前置筛选同时考虑预测证据、换手、≥30 笔/90 天可达性及成本后收益，
  禁止只优化 RankIC。
- **FR2.4 纯度与能力边界**：因子通过 AST 纯度门；前视、网络访问、隐式全样本统计和未支持的跨 pair
  算子直接拒绝，不得静默降级。
- **FR2.5 因子注册表**：保存定义、参数、数据依赖、来源、版本、评测摘要和生命周期；IC/OOS PnL
  高相关候选查重，`|ρ|>0.99` 拒绝，`0.90~0.99` 标记变体。
- **FR2.6 探索组合**：AlphaGen 协同池作为可部署 meta-factor 注册；名义产量、有效独立数、来源多样性
  与资源消耗并列记录，禁止只用公式数量汇报产能。

### FR3 证据评测与验证

- **FR3.1 统一评测台**：输入 FactorDef 或已冻结 PortfolioDef 和显式窗口。因子报告输出 RankIC、
  IC 衰减、分状态和分位数收益；组合报告输出收益风险、换手、容量、持有期和毛交易摘要。
  评测台不自行选择窗口或改变组合成员。
- **FR3.2 成本模型**：交易费、滑点、资金费率进入选择回路；taker/maker/零成本三档为标准输出，
  成本后收益不为正则 `dead`。参数以 dry-run 实际成交校准并带 `cost_model_version`。
- **FR3.3 多重检验与独立性**：每条进入评测的表达式（含拒绝者）在预注册 cohort 内计一次试验；
  基于 cohort 全部表达式执行 BH-FDR、deflated significance/白噪声对照，并用选择期 purged CV
  的 OOS PnL 聚类估算有效独立数。cohort、试验定义和选择阶段必须在看结果前冻结。
- **FR3.4 验证顺序**：规则在看数据前固定；FactorDef 粗筛/选择期 → FR4 构建并冻结 PortfolioDef
  → PortfolioDef 最终 90 天留出 → 永久隔离最终确认窗。每周进入最终留出的组合候选上限默认 5，
  所有访问写 append-only 台账。不得先读取留出结果再新建或修改组合。
- **FR3.5 样本量裁决**：少于 30 笔为 `UNDERPOWERED`；30~69 笔最多临时 PASS，只允许缩减仓位
  paper；约 ≥69 笔才可形成可信判定并参与北极星计数。
- **FR3.6 无前视三层审计**：AST 纯度、独立逐 K 线重放、信号缓存 merge/join 时间戳与陈旧度检查
  全部通过才可晋级；切分以 label endpoint 为边界，按 pair 的 point-in-time 可交易日历处理，
  embargo 不短于最大标签 horizon，拟合型变换只在训练折拟合。
- **FR3.7 第二实现复核**：高价值候选、评测差异或系统升级时用独立实现复核。Vibe-Trading 可在 1 周
  time-box 内提供 local loader、Bootstrap/Walk-Forward 和回测对照；超时则用独立重放器或手工第二
  实现，不阻塞主链路。
- **FR3.8 正控制与漏斗**：funding carry、BTC/ETH 截面动量同期跑完整门禁；逐级记录 §2.3 漏斗，
  周报必须指认最大流失级。
- **FR3.9 证据执行层级与失败语义**：所有运行显式声明 `preview | canonical`。preview 写隔离产物，
  不进入 official population、不消耗留出预算、不访问永久确认窗且不能晋级；canonical 才可正式
  计数与裁决。必需指标计算失败或 parity 被跳过时必须 `INCOMPLETE/FAIL`，不得以 warning、空值
  或 skip 放行。

### FR4 组合与策略构建

- **FR4.1 统一可部署对象**：任何待部署策略都表示为 PortfolioDef；单因子策略是单成员组合，协同池
  meta-factor 是组合成员或已冻结的单一信号对象，均不因来源获得豁免。
- **FR4.2 组合门**：只用选择期及更早数据，报告候选对现有基准组合的边际收益、边际回撤、相关性和
  容量；无正边际贡献者不进入待验证 PortfolioDef。
- **FR4.3 Top-K、权重与冻结**：按选择期成本后指标选 Top-K（v0.1 K=3，硬上限 5），用选择期估计的
  逆波动率权重构建 PortfolioDef。成员、权重、阈值和约束在进入留出前冻结；最终门禁验证的是完整
  PortfolioDef，不是事后拼接的一组已通过因子。
- **FR4.4 交易约束**：单周期换手默认 ≤100%；同 pair 方向冲突在组合层净额化；净敞口、风险预算、
  最小订单和容量约束先于信号缓存执行。
- **FR4.5 防泄漏**：成员选择、Top-K、权重、阈值和边际贡献门只使用选择期及更早数据；估计窗口写入
  manifest。看过留出或最终确认结果后改变任一字段，必须生成新 PortfolioDef 并从头消耗门禁预算。

### FR5 部署与交易执行

- **FR5.1 版本化信号契约**：feather 按日分片，包含 timestamp、pair、signal、confidence、stale；
  缓存键含 factor/portfolio、data_version、code_version 和 params_hash，旧版本只读不覆盖。
- **FR5.2 部署前复核**：最终确认通过不等于当前仍有效；挂载前在晚于留出窗的最近窗口复核，
  challenger 替换 champion 时重复执行。
- **FR5.3 Freqtrade 适配**：策略模板负责读缓存、进出场和风险钩子；执行引擎不重新解释因子逻辑，
  留出通过至 dry-run 可挂载时间 ≤1 天。
- **FR5.4 渐进发布**：backtest → dry-run → paper → live 逐级晋升；每一级有独立配置、审批和回滚。
  v0.1 交付边界止于 paper，live 必须另行确认且满足 ADR-0003。
- **FR5.5 风控不可绕过**：CircuitBreaker、CorrelationGuard、DrawdownGuard、仓位和订单约束在所有
  paper/live 路径生效；Agent 无下单权和绕门权限。
- **FR5.6 执行回流**：订单、成交、拒单、滑点、资金费和风险事件关联到 portfolio/factor/experiment
  版本，供成本校准和归因使用。
- **FR5.7 决策时一致性与恢复**：进入 dry-run/paper 前验证离线特征→预测→仓位→order-intent
  与决策时路径一致；跳过检查即失败。运行记录区分 intended/attempted/accepted/failed 四桶，
  kill-switch 状态持久化，进程启动时先完成未决订单和状态对账再恢复执行。

### FR6 监控、归因与学习闭环

- **FR6.1 全链路可观测**：统一监控数据延迟/缺失、信号新鲜度、IC/收益衰减、组合 PnL/回撤、
  成交偏差、成本漂移、风控事件、实验漏斗与生命周期状态。
- **FR6.2 生命周期动作**：状态至少包括 proposed/evaluating/validated/champion/challenger/monitoring/
  decayed/disabled；阈值触发降权、暂停或下线，恢复必须重新验证。
- **FR6.3 结构化归因**：失败和线上偏差同时记录 `failure_stage`（信号质量、组合转换、成本/容量、
  时序稳定、执行实现）、`failure_owner`（数据、信号、市场状态、成本、组合、执行、风险）和
  `failure_mechanism`（技术分歧、统计衰减、结构变化等）；报告链接原始证据，并严格区分事实、
  推断与建议。三个维度互补，不用阶段标签替代责任分类。
- **FR6.4 AI 复盘**：Agent 只读允许的数据与报告，输出可人审的新假设草案；不得看到永久隔离确认窗，
  不得直接改变生产状态。Vibe-Trading 是可替换提供者，不是闭环唯一实现。
- **FR6.5 反馈入队**：人审通过的新假设带来源和 generation 回到 FR2，并完整计入多重检验和留出预算。

### FR7 实验治理与可复现

- **FR7.1 统一 manifest 与内容身份**：记录 hypothesis/factor/portfolio ID、execution tier、cohort、
  data/code/cost model 版本、参数、窗口、随机种子、确定性开关、依赖版本、结果摘要和结论。
  `experiment_id` 由上游 ID、cohort、规范化语义配置、数据值摘要、代码/构建摘要和种子导出；
  execution tier、supersedes、路径、时间、主机与 Parquet 编码不参与身份。
- **FR7.2 不可变证据链**：评测报告、毛交易摘要、留出访问、组合决策、信号缓存、部署审批和运行结果
  通过稳定 ID 关联；历史产物只增不改，语义变化生成新 ID 并以 `supersedes` 保留谱系。
- **FR7.3 可重算与重定价**：历史结果可从 manifest 重建；成本模型变化时优先基于逐笔毛交易或等效
  摘要重定价，不要求重新运行因子生成。
- **FR7.4 决策审计**：裁决、晋级、降权、下线和 pivot 记录规则版本、证据、操作者与时间；人工覆盖
  必须留痕，且不能覆盖硬安全门。
- **FR7.5 周期综合报告**：每周从 canonical experiment ledger 与曲线侧车生成版本化
  `synthesis_report`，报告北极星领先指标、cohort 漏斗、有效独立数、来源多样性、资源消耗、
  五阶段损失、线上偏差和最大约束；事实、推断、建议分栏，不以名义候选数单独宣告成功。

### FR8 呈现与审查界面

呈现层的实现路线（真相源/投影/展示三分、自建前端次序、工具降级）见 ADR-0005；本节只约束
产品行为。

- **FR8.1 研究证据浏览**：因子、组合与实验的版本化报告、权益/回撤/分位数/IC 曲线和实验谱系
  经统一只读界面浏览；研究控制台先于 M2 周产能爬坡上线。界面渲染对象仅限可追溯 manifest 的
  版本化产物，实时运营数据不进入研究界面（运营观测走监控栈）。
- **FR8.2 口径与呈现分离**：指标口径唯一居所为版本化数据视图；任何呈现前端（Grafana 看板或
  自建页面）均为薄渲染器。新旧呈现并存期对数必须一致。
- **FR8.3 人审与运营操作入口**：假设人审入队（FR6.5）、部署前复核审批（FR5.2）与生命周期
  动作（FR6.2）经统一 API 完成；前端不直写生产状态，全部操作落 FR7.4 审计。
- **FR8.4 裁决不页面化**：门禁与统计裁决保持确定性脚本路径，界面只呈现裁决结果，不提供
  裁决按钮。

## 五、非功能需求与安全红线

| 类别 | 要求 |
|---|---|
| 可复现 | 任一历史结论可由 manifest、不可变数据和锁定代码从零重建 |
| 无前视 | 因子、组合、缓存对齐和 Agent 输入均遵守时间边界；前视泄漏容忍度为 0 |
| 成本现实 | 费用、滑点、资金费率和执行偏差均版本化，并由实际成交持续校准 |
| 确定性 | AI 输出只能成为候选或建议；统计裁决、风控与执行由确定性代码完成 |
| 安全 | 密钥仅存 `.env`/凭据库；服务默认本机回环；无明确审批不得开启 live |
| 资源 | 以单机 RTX 4060 Laptop GPU 为基线；GPU 任务排队，CPU 评测可夜间批跑 |
| 可替换性 | 生成器、第二意见回测和 Agent 提供者经本仓契约接入，单一外部依赖失败不阻塞闭环 |
| 质量门 | 每个里程碑有可运行验收；项目统一入口为 `python3 tools/verify.py` |

## 六、里程碑

| 里程碑 | 产品能力 | 出口标准 | 预估 |
|---|---|---|---|
| **M0 自包含运行基线** | quant-crypto 采集、Kronos、风控、监控和 Freqtrade 资产清算迁入；历史数据自交易所重建（原数据卷灭失，见 F001 spec §0 路线修订） | 回填完整性校验、Kronos `/health`、采集、dry-run、监控和恢复演练全绿 | 2~3 天 |
| **M1 可信数据与证据底座** | FR1 + FR3 评测台/门禁骨架 + FR7 manifest 基础 | 任意 FactorDef 可从不可变快照以显式 preview/canonical 层级产出版本化报告；label endpoint/PIT/methodology 门可失败关闭；正控制、种子相关性矩阵、成本分解三项探针完成 | 1 周开发 + 1~2 周回填（并行） |
| **M2 AI 因子工厂** | FR2 + 自动漏斗 + 实验谱系 + FR8.1 研究控制台（先于周产能爬坡上线） | AlphaGen 冒烟通过或按 ADR-0001 降级；单次 ≥50 候选自动评测；周产能可达 ≥100 且报告有效独立数；研究控制台可浏览版本化报告与曲线（权益/回撤/分位数/IC 衰减），与 `report.json`/`curves.parquet` 对数一致（FR8.1） | 2 周 + 研究控制台约 1 周 |
| **M3 策略到 paper 闭环** | FR4 + FR5 | 单成员/多成员 PortfolioDef 在选择期冻结并以整体通过门禁、信号缓存、决策时 parity 和部署前复核后进入 dry-run/paper；run_record 四桶、持久化 kill-switch 与启动对账通过故障注入；正控制或历史候选完成一次全链路技术验收；最终确认通过至挂载 ≤1 天 | 1~2 周 |
| **M4 运营与学习闭环** | FR6 + FR7 + FR8.3 人审与运营操作入口 | 监控可触发生命周期动作；首份结构化复盘产生人审后的下一代假设并重新入队；周报输出完整指标体系；论题检查点开始计时；人审入队与生命周期动作经统一 API 完成并落 FR7.4 审计（FR8.3） | 持续 |

M1 三项论题探针：正控制报告；GTJA191 子集与 Kronos 的 OOS PnL 相关性聚类基线；taker 费、
资金费率和滑点对毛 Alpha 的成本分解。

Vibe-Trading 不拥有独立里程碑。在 M1~M4 需要第二实现或 AI 复盘能力时可进行一次 1 周 time-box
接入；失败即使用本仓独立重放器、手工第二实现或其他 Agent 提供者，不改变里程碑出口。

## 七、主要风险与应对

| 风险 | 应对 |
|---|---|
| 名义吞吐增长但有效探索不增长 | 名义数与有效独立数并列；来源多样性和 OOS PnL 聚类进入周报 |
| RL/LLM 奖励投机、泄漏或批量伪因子 | 生成与裁决分权；纯度门、独立重放、白噪声、多重检验和永久确认窗 |
| 信号成本后不可交易 | 成本与换手进入生成目标和硬门；实际成交持续校准并保留重定价摘要 |
| 单因子有效但组合无增量价值 | 组合门衡量边际收益/风险/容量；Top-K、净额化和风险预算前置 |
| 研究 PASS 到部署时已经衰减 | 部署前最近窗口复核；champion/challenger 轮换触发再验证 |
| Agent 复盘扩大数据窥探 | generation 标记、试验预算、确认窗隔离、人审入队、无生产写权限 |
| 外部工具绑架主链路 | 全部经稳定契约接入；Vibe-Trading 可弃置；Freqtrade 不改源码 |
| 长期零可信 Alpha 被合理化 | §2.6 预注册时钟、正控制与三分支决策，不允许默认续期 |

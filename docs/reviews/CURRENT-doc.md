# AlphaMill 检视报告（第 3 轮 · 目标与计划专项）

## 1. 总评

**用户核心问题："开始开发后出现大规模方向变更"的风险在哪里？**

结论：**架构层大半天然免疫方向变更，风险集中在论题经济学与核心回路内部，共 7 处（2 High / 4 Medium / 1 Low），全部是"现在改=半天文档工作、开发后改=返工"的类型。** 修完这 7 条后，方向变更若发生，都是预先设计好的分支决策，而不是危机。

两条 High 的共同症状值得警惕：**它们都表现为"系统绿灯运转但零存活者"**——与 quant-crypto 的死法同型，只是这次系统更大、跑得更久、更难归因。

### Pivot 免疫地图（正面资产确认，修复时不得破坏）

| 方向变更场景 | 代价 | 依据 |
|---|---|---|
| 换频率（1h/4h/1d 之间） | ≈0 | 1m 原始湖是母集，重采样即得 |
| 换执行引擎/风控 | ≈0 | Freqtrade 插件层零源码改动 |
| 弃置 Vibe-Trading | 低 | 上层建筑，声明可弃置即可（D031） |
| 换挖掘引擎 | 低 | L1/L2 降级阶梯（ADR-0001）为此设计 |
| 宇宙扩容（6→30-50 对） | 中 | 1m 湖+回填已显式化（D007 修复），非免费但已规划 |
| **换验证栈校准数字（成本模型/窗口/门槛）** | **高** | **唯一贵的核心；全部风险都在这附近聚集（D027/D029/D030）** |

### 六个月情景排序（检视人+Oracle 独立一致）

1. **(c) ~35%**：有效独立假设吞吐量才是真约束 → 转向假设源多样性（种子库+复盘循环）。FR2.4 已预承认此约束，D028 的 M1 探针顺手启动该路径的准备——最不意外、最可能。
2. **(b) ~30%**：成本墙杀掉一切 → maker-only/低换手 pivot。≥30 笔门槛强制活跃度，活跃度撞 taker+资金费率，张力是结构性的。
3. **(a) ~25%**：论题成立出存活者。门禁诚实，出了存活者成色就高。
4. **(d) ~10%**：彻底放弃 RL 挖掘。L1/L2 阶梯已制度化部分撤退，全弃比降级少见。

联动信号：若 M1 种子相关性矩阵显示种子库独立性是 AlphaGen 输出的 3 倍以上，(d) 上调。

## 2. 关键推导链（D025 的算术，修复方应理解后再修）

- G1 算术：100 候选/周 × 1-5% 诚实 OOS 通过率 = 1-5 存活/周。
- FR2.4 修复（Round 1 D004）：候选共享数据/奖励/协同池，**有效独立假设仅 5-10/周**。
- 联立：5-10 × 1-5% = 0.05-0.5 存活/周 → **每 2-20 周一个存活者，全年 2.6-26 个**。
- 更糟的修正（Oracle）：1-5% 通过率是"到达留出的候选"的条件概率，成本硬过滤进一步缩小分母。
- 分布形态：几何/泊松型重尾等待。中位假设（λ=0.25/周）下 8 周零存活概率 ≈13.5%，12 周 ≈5%；悲观角（λ=0.05/周）下 26 周零存活概率 ≈27%——**"长期零存活"在论题成立的情形下也是常见事件**，这正是需要预注册判读框架的原因。

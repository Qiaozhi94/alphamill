# v0.2 收口摘要

> 本文件记录 v0.2 已 `done` 的 Feature 交付内容。活跃 Feature 见 `BACKLOG.md`。

## F009：Kronos 服务生命周期控制面端点（2026-09-24 收口）

- **交付**：`kronos-signal-real` 暴露 `GET /lifecycle/status`、`POST /lifecycle/stop`、
  `POST /lifecycle/restore`，行为与架构 §7.1 动作表逐格一致：版本协商与单键错误信封、
  期望态 `desired` 与三值派生态（含 `transitional`）、单飞仲裁（`E_BUSY` 不排队）、
  `E_TIMEOUT` 表示"动作仍在进行"且不中断后台、失败落点按"不可逆的一步是否已发生"收敛。
- **本 feature 的真正增量**：`stopped` **待得住**——`desired=stopped` 期间推理端点不再隐式
  重载模型（走 F004 既有兜底路径、来源不标 `kronos`）。没有这一条，`stop` 之后任何一次
  `/predict` 都会把显存吃回去。
- **配套**：显存探测三级回退（不查 GPU 进程列表）与五个环境变量的值域/启动期判红；
  logfmt 结构化日志 + 超时后迟到完成的 `late_complete` 收尾行；控制面端口绑 `127.0.0.1`
  （同提交内迁移 F004 端口契约，原意不变）。
- **执行机证据**（`qiaozhi-lt`，CPU 实例）：契约套件 `--runxfail` 6 passed / **0 xfailed**；
  mock 实例三端点 404（新镜像带着控制面代码但不注册路由）；夜槽旅程 running → stop →
  5 次 `/predict` 全走兜底且 `model_loaded` 恒 false → restore → 恢复 `source=kronos`。
- **显存结论的边界**：`tests/integration/test_f009_vram_release.py` 以 `xfail(strict=True)`
  保持先红态——真实显存下降的取证与解除归 **F010**（其 AC-009/T011），两者不互相等待。
- **代码检视**：3 轮 10 条全闭（1 条修复引入、1 条规格自身不可满足经 owner 裁决拆边界），
  完整 issue 表与模式教训见 `docs/reviews/RETROSPECTIVE.md` 循环 19。收口 CI：35995587247。

## F010：Kronos GPU 推理基座（2026-09-25 收口）

- **交付**：`kronos-signal-real` 可在执行机以 CUDA 加载并产出真实信号。torch 的版本与 wheel
  索引由 Dockerfile 构建参数驱动（缺省仍是 `2.14.0` + CPU wheel，默认构建命令与落地前等价）；
  GPU 面（独立镜像标签、`cu130` 索引、`KRONOS_DEVICE: cuda`、nvidia × 1 设备预留、以
  `device` 以 `cuda` 开头为判据的 healthcheck）只在 `deployment/docker-compose.gpu.yml`
  叠加层出现，默认 compose 与 `.env.example` 未改。
- **失败可见**：显式 `KRONOS_DEVICE=cuda` 而拿不到 CUDA（CPU wheel 或无设备）时，启动、
  F009 `restore`、`/predict` 惰性加载共用的加载入口直接抛错，不静默回落 cpu；显式值只接受
  `cpu` / `cuda` / `cuda:0`。
- **执行机证据**（`qiaozhi-lt`，RTX 4060 Laptop / 驱动 616.64 / torch `2.14.0+cu130`）：
  `/health` 报 `device=cuda:0`、真实信号 `source=kronos`；常驻显存峰值 **565 MiB**（≤3GB 预算，
  不重标）；夜槽旅程 565 → `stop` → 137 MiB、整卡可用 7820 MiB ≥ 6GB → `restore` 恢复。
- **下游解锁**：`tests/integration/test_f009_vram_release.py` 的 `xfail(strict=True)` 已移除并
  真实通过（F009 AC-012）；F003 `vram_limit_gb` 缺省 6.0 与架构 §7.1 夜槽行均不重标。
- **运维前置**：执行机须装 nvidia-container-toolkit；构建用 host 网络 buildx builder；
  到 pypi.nvidia.com 不通时在本机 `deployment/.env` 给 `TORCH_EXTRA_INDEX_URL`
  （见 `docs/alphamill-integration.md` §七）。
- **代码检视**：3 轮 17 条全闭（7 条修复引入，含 1 条 High），完整 issue 表与模式教训见
  `docs/reviews/RETROSPECTIVE.md` 循环 20。PR #6 CI：36034315951。

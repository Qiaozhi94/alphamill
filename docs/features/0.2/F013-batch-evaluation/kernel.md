# F013 意图内核：把已完成生成批次送入可恢复的正式评测闭环

## Why

F012 已能入册 50 个候选，但生成与 F007 单候选评测之间仍有五处契约缺口。
运营者需要一次确定性执行拿到整批可追溯的评测与漏斗，而非手工拼接输入和挑选结果。

## Capabilities

- C1：将生成绑定转换为已发布 ResearchSnapshot，整批及续跑始终引用同一快照（AC-001/002）。
- C2：从 FactorDef 生成可复算信号 CSV 与保留算子窗口的表达式串（AC-003/004）。
- C3：适配生成事件，拒绝原因、来源和计数守恒可核对（AC-005）。
- C4：结果产生前冻结全部成员，canonical 有界重试、终态登记、finalize 与 synthesis 可恢复（AC-006/007/008）。
- C5：报告名义分母、有效独立数、来源分布及最大流失级，完成执行机性能取证（AC-009/010/011）。

## Constraints

只读不可变湖；沿用 ADR-0003/0006/0007/0008；确定性非 Agent 脚本才可进入 canonical；
不以退出码、数量或 FINALIZED 状态代替门禁裁决；本次仅交付需求设计，不执行开发任务。

## Non-goals

不做 UI、Agent 自主正式裁决、生成算法加速、协同池注册或实盘部署。
不将 F013 收口等同于 M2 出口验收，不设候选盈利或周产量指标。

## Success signal

运营者对一个 completed run_dir 执行批量命令，中断后重跑仍只有原承诺成员各一次正式计数，
并能从同一快照和正式台账重建含来源分布与最大流失级的报告。

# ADR-0003：验证门禁不降级 —— quant-crypto 教训制度化

- 日期：2026-09-06
- 状态：Accepted
- 决策人：Georg
- 背景：`D:\Projects\quant-crypto` Phase 4 决策报告（2026-06-17，`blocked_no_paper_candidate`）与
  PRD G2 / FR3
- 修订：2026-09-07（检视 D005/D006/D008 补强：留出预算 / 功效论证 / 复盘防护；下列"决策"节
  判据本体一字未动，补强只收紧、不放松）

## 背景

quant-crypto 的最终 90 天留出门连续拦下全部候选（低频 Ridge/HGB、regime 增强、成本感知、
衍生品 basis），看起来是"失败"，实际是验证协议在正确工作——它拦下的是会亏钱的东西。
真正的问题是 alpha 供给量（每周 ~5 个假设）与留出期样本量不足（69 笔交易的 FAIL/PASS
判定统计上不可信；regime filter 方向正确但 27 笔欠功效）。

该门禁的价值来自它**从不放水**。任何"先上盘再观察"的妥协都会摧毁整个系统的可信度。

## 决策

1. **留出门不降级**：任何候选必须通过最终 90 天留出才能进入 paper/实盘——此规则从
   quant-crypto 原样继承，永不为吞吐量让路。
2. **样本量门槛**：留出期 ≥30 笔交易才允许 FAIL/PASS 判定；样本不足输出 `UNDERPOWERED`
   （不判 PASS 也不判 FAIL），触发扩宇宙/延长窗口，而不是放行。
3. **无前视是一等公民**：AST 纯度门（因子定义层）+ 独立逐 K 线重放审计（策略层）+
   信号缓存时间戳对齐检查（数据层），三层全部通过才算干净。
4. **成本三档为标准输出**：taker / maker / 零成本三档敏感性进入每个候选的评测报告，
   成本后 Sharpe 为排序主键。
5. **实盘前置条件不变**：没有留出通过的候选，不触碰实盘下单路径（PRD 非目标硬约束）。

## 留出期使用预算（2026-09-07 补强 · D005）

留出窗口是**可耗竭的统计资源**：5000 候选/年过同一个 90 天窗，窗口在统计上退化为训练集，
"从不放水"的可信度随之蒸发。补强规则（判据本体不动）：

1. **周度访问预算**：每周允许进入最终留出评估的候选上限 top-k，v0.1 默认 k=5（配置项，
   `validation/config.yaml`）；未获配额的候选排队下一周期，不得"顺手多跑一个"。
2. **留出使用台账**：append-only，每次留出评估一行——候选 ID、日期、判定结果；台账与
   manifest 同为可复现要件。预算消耗以台账为准，不支持事后补记。
3. **永久隔离的最终确认窗**：一段独立数据片段，开发期任何候选（含评测台/选择期/复盘循环）
   均不得接触，仅在候选晋升 paper 前使用一次——最终确认窗上的判定为终局判定。

## 样本量门槛的功效论证（2026-09-07 补强 · D006）

PRD §1.2 自身诊断："69 笔交易的 FAIL/PASS 判定统计上不可信"，而决策 2 只设了 ≥30 笔。
显式澄清如下（≥30 的硬下限不变，只新增限制）：

- **≥30 笔是绝对硬下限**，不是可信判定的充分条件：低于 30 笔连评估资格都没有，直接
  `UNDERPOWERED`。
- **30~69 笔 = UNDERPOWERED 带**：该区间内即使指标达标，判定也仅为**临时 PASS**——只允许
  进入缩减仓位的 paper 试运行 + 延长观察期（观察至样本跨过 69 笔或触发衰减下线），
  不构成可信判定，不得用于任何实盘前置论证。
- **可信判定需要 ≈69 笔及以上**：α=0.05、80% 功效下，最小可检测效应对应的样本量即在该
  量级——PRD §1.2 对"69 笔不可信"的诊断正说明 69 笔只是功效勉强及格的下界，30 笔
  显然更不可信。
- 本补强使门禁**实际更严**：30-69 带新增的是限制（临时 PASS + 缩减仓位）而非豁免。

## 复盘循环窥探防护（2026-09-07 补强 · D008）

FR4.3 的 agent 复盘循环（读结果 → 产假设 → 同一段历史再测）是数据窥探放大器：假设生成与
评估共用同一数据，多重检验风险随代次累积。补强规则：

1. **代次标记**：复盘循环产出的每条假设带 generation 标签（来源 = review-loop，代次 =
   第几轮），与普通候选一样计入试验台账（与留出使用台账同一台账体系）。
2. **试验预算计入**：复盘假设的每一次评估计入 PRD FR2.4 的多重检验预算——人工/agent
   产出的假设不享受任何豁免，与程序化候选同一口径计数。
3. **最终确认窗隔离**：上一节定义的永久隔离最终确认窗对复盘循环不可见——agent 的输入
   （manifest + 报告）不得包含最终确认窗上的任何统计量；确认窗只在晋升 paper 前
   使用一次。

## 后果

- 正面：系统永远不会因为"看起来能赚"而部署过拟合候选；失败案例可归因、可沉淀。
- 负面：出结果慢是设计使然；吞吐量的提升必须来自假设数量（因子工厂），而不是放宽门禁。
- 执行：门禁逻辑落在 `validation/`（holdout_gate / no_lookahead_audit），机器可校验部分进
  verify；语义覆盖由 review 人工判断。

# ADR-0003：验证门禁不降级 —— quant-crypto 教训制度化

- 日期：2026-09-06
- 状态：Accepted
- 决策人：Georg
- 背景：`D:\Projects\quant-crypto` Phase 4 决策报告（2026-06-17，`blocked_no_paper_candidate`）与
  PRD G2 / FR3

## 背景

quant-crypto 的最终 90 天留出门连续拦下全部候选（低频 Ridge/HGB、regime 增强、成本感知、
衍生品 basis），看起来是"失败"，实际是验证协议在正确工作——它拦下的是会亏钱的东西。
真正的问题是 alpha 供给量（每周 ~5 个假设）与留出期样本量不足（69 笔交易的 FAIL/PASS
判定统计上不可信；regime filter 方向正确但 27 笔欠功效）。

该门禁的价值来自它**从不放水**。任何"先上盘再观察"的妥协都会摧毁整个系统的可信度。

## 决策

1. **留出门不降级**：任何候选必须通过最终 90 天留出才能进入 paper/实盘——此规则从
   quant-crypto 原样继承，永不为吞吐量让路。
2. **样本量门槛**：留出期 ≥30 笔交易才允许 FAIL/PASS 判定；样本不足输出 `UNDERPOWERED`
   （不判 PASS 也不判 FAIL），触发扩宇宙/延长窗口，而不是放行。
3. **无前视是一等公民**：AST 纯度门（因子定义层）+ 独立逐 K 线重放审计（策略层）+
   信号缓存时间戳对齐检查（数据层），三层全部通过才算干净。
4. **成本三档为标准输出**：taker / maker / 零成本三档敏感性进入每个候选的评测报告，
   成本后 Sharpe 为排序主键。
5. **实盘前置条件不变**：没有留出通过的候选，不触碰实盘下单路径（PRD 非目标硬约束）。

## 后果

- 正面：系统永远不会因为"看起来能赚"而部署过拟合候选；失败案例可归因、可沉淀。
- 负面：出结果慢是设计使然；吞吐量的提升必须来自假设数量（因子工厂），而不是放宽门禁。
- 执行：门禁逻辑落在 `validation/`（holdout_gate / no_lookahead_audit），机器可校验部分进
  verify；语义覆盖由 review 人工判断。

# ADR-0005：呈现与观测架构 —— 真相源/投影/展示三分与自建前端路线

- 日期：2026-09-13
- 状态：Accepted
- 决策人：Georg
- 背景：呈现层长期路线；PRD FR8 / FR6.1 / FR6.4 / FR7.2 / FR7.4；架构文档 §〇 / §七

## 背景

当前呈现面三件：Grafana（`quant-overview` 平台观测 + `dryrun-monitoring` 策略运营，F001
迁入并验收有数）、FreqUI（Freqtrade 镜像自带，`api_server` 已启用）、CLI（`tools/verify.py`
门禁与操作）。三个结构性问题随里程碑逼近：

1. **研究证据没有承载面**：评测台（FR3）落地后 M2 出口要求周产能 ≥100 候选，版本化报告
   靠文件浏览不可持续；架构文档 §五 原计划的「Grafana 实验台账看板」与版本态产物形态
   （文件 + 谱系图 + 逐因子下钻）不匹配。
2. **口径被困在看板里**：dashboard JSON 内嵌 SQL 会持续积累业务口径（成本后收益、胜率、
   延迟判定等），更换呈现工具即全部重写；且新旧两套实现并存期必然漂移——「哪个数字是
   真的」在量化系统中是不可接受的风险。
3. **工具边界不清**：FreqUI（执行显微镜）、Grafana（运营观测）、未来页面（研究证据）
   各自该看什么、数据从哪来、谁能写什么，无明文约定。

长期意图：项目若持续推进，**前台页面最终全部自建**。呈现工具是租客，不是资产；资产是
口径（视图）、数据通路（API）与真相源本身。

## 决策

1. **三分边界：真相源 / 投影 / 展示**

| 层 | 内容 | 变更纪律 |
|---|---|---|
| 真相源 | 研究=不可变报告文件 + manifest；运营=TimescaleDB 原始表；执行=Freqtrade（自身库 + REST） | 不可变或版本化；任何展示数字必须可追溯至此 |
| 投影 | 版本化 SQL 视图（TSDB，入 `db/migrations/`）+ 统一只读 API | 必须可从真相源确定性重放/重建，禁止手工改投影 |
| 展示 | Grafana 板、自建 SPA、FreqUI | 薄渲染器，可随时替换，不承载口径 |

2. **口径唯一居所是 SQL 视图**：指标口径一律定义为视图并入 `db/migrations/`；Grafana
   面板只允许 `SELECT ... FROM 视图 + 过滤参数`，禁止承载口径；自建页面消费同一批视图。
   任何新旧呈现并存期，**对数 diff=0 是迁移验收标准**（旧看板即新页面的 golden master）。

3. **统一只读 API 是永久人类界面后端**：`src/alphamill/api/`，端点按领域对象组织
   （hypotheses / factors / portfolios / deployments / manifests / runs / ops-metrics /
   trades）；执行明细**代理 Freqtrade REST**（稳定契约，不直连其 SQLite）。未来写路径
   （人审队列、生命周期动作、部署审批）唯一经此层，并在该层落 FR7.4 审计；**前端永不
   直写 DB**。

4. **研究面自建先行（F005，评测台落地后、M2 开闸前）**：只读研究控制台 = 上述 API +
   `web/` SPA（构建产物静态文件由 API 服务托管，**生产运行时无 Node**）+ lightweight-charts。
   渲染对象**仅限版本态产物**：因子列表与指标对比、单因子曲线组（权益/回撤/分位数/IC
   衰减）、谱系与漏斗。**谱系归 F005**；**台账只读视图为后续增量 F005.1**，组合只读视图
   （M3+）另立 spec 或并入 M3 规划，均不属 M2 前窗口。
   **实时 PnL 不进控制台**，跳转运营面。

5. **工具定位与降级路线**：
   - **Grafana 终局退守平台观测 + 告警引擎**；策略运营板随自建运营面落地后删除；
     **不做研究看板**（修订架构文档 §五 原计划的「实验台账看板」）。
   - **FreqUI 降级为应急操作面板**（forceenter/forceexit/启停），日常不打开；其只读明细
     由自建运营面承接。
   - **门禁裁决永不页面化**：`tools/verify.py` CLI 是唯一入口，页面只呈现裁决结果，
     不提供裁决按钮。
   - **告警评估与通知路由不自建**——交易系统生命线，不自造轮子。

6. **自建增量次序**（每步独立有价值、可随时停）：研究面（M2 前）→ 业务运营面（M3/M4，
   实时 PnL/持仓/逐笔，读视图 + Freqtrade 代理）→ 平台观测面（最后）。每步替换模式固定：
   新页面读同一批视图/API → 与旧板对数 → 删旧板。

7. **视觉原型是全景蓝图，不是 F005 范围**：`docs/design/ui-mockup/` 是覆盖终局四面
   （研究 / 运营 / 平台 / 应急）的静态原型，用于锁定信息架构、面板密度与交互形态。
   F005 只实现其中的研究面（决策 4 的渲染对象）；运营面归 M3/M4 自建运营面（写路径与
   审计归 F006）、平台面归告警栈末端（决策 5）、应急面归 F006。跨面实时读数
   （运营 PnL/持仓等）仅作蓝图占位，**研究控制台不得渲染**（决策 4），原型各页顶部已
   标注该页归属的 feature / 里程碑。原型是设计资产而非契约：不产生接口、不参与验收；
   F005 spec 落地后按 `docs/README.md` 所有权约定废弃或迁入 `web/`。

## 备选方案

- 方案 A（选定）：视图/API 资产化 + 研究面自建 + Grafana 退守告警。
- 方案 B：Grafana 全承载（研究结果投影进 TSDB 后全部用 Grafana 看）。优点：零前端工具链、
  单一工具。缺点：下钻深度、谱系图、富文本证据呈现触及体验天花板；投影表易被当成第二
  真相源。保留为后备路径——本 ADR 的视图/投影建设方案 B 完全复用，切换无沉没成本。
- 方案 C：维持现状（Grafana + 文件浏览）。缺点：M2 规模下报告消费不可持续，口径持续
  困在看板 JSON。

## 后果

- 正面：口径单点且版本化；Grafana 阶段的投入（视图/板）成为终局资产；日常入口最少化
  （一个 SPA + 一个告警引擎）；每步迁移小且可逆。
- 负面/义务：前端**构建期**工具链成为新依赖（pin + 里程碑边界升级，按 ADR-0002 纪律；
  运行时零新增）；过渡期两套呈现并存需执行对数纪律；自建页面工作量由项目承担。
- 约束传播：**F007 spec 已包含「评测报告持久化曲线级时间序列（权益/回撤/分位数收益/
  IC 衰减），Parquet + manifest 关联」**，并将 `synthesis_report` 定义为 F005 的只读输入；
  本决策的呈现依赖已在 F005 开发前锁定。
- 后续行动：① 立 F005 研究控制台 spec（引用本 ADR，版本归属 0.2）；② 现有 Grafana 两板
  随需瘦身为视图渲染（口径逐步下沉 `db/migrations/`）；
  ③ F005 立项时扩展 `tools/check_dep_pins.py` 覆盖前端构建期依赖（Node 主版本 +
  `package-lock.json` 完整性），使「按 ADR-0002 纪律 pin」成为可机器校验的门禁；验收判据：
  对 `package-lock.json` 做一次变异验证（改一个依赖版本号使门禁变红），F005 立 spec 时
  转入其 tasks.md。

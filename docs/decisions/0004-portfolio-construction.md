# ADR-0004：组合构建层 —— 协同池组合可部署化与 Top-K 策略映射

- 日期：2026-09-07
- 状态：Accepted
- 决策人：Georg
- 修订：2026-09-07（检视 D027 补强：池构建 / Top-K / 逆波动率估计窗的留出前数据边界；决策本体未动）
- 背景：检视报告 D001（[`docs/reviews/CURRENT-doc.md`](../reviews/CURRENT-doc.md)）；集成文档 §四 的
  Top1-only 部署政策；PRD FR2.1 / FR5

## 背景

AlphaGen 主引擎的核心产出是协同池（LinearAlphaPool：基础因子的线性组合，增量 IC reward
机制性防冗余），但当前部署设计只有两条路：单因子单策略模板（集成文档 §3.3）+ 多候选同过
留出时取 Top1 进 dry-run（集成文档 §四）。结果是：

1. **组合 alpha 没有部署路径**——主引擎最有价值的输出在系统里是死产出；
2. Top1-only 同时丢弃了多存活因子的组合价值：N 个存活因子 = N 个独立策略的替代方案，
   资本碎片化、费用×N、同一 pair 上多空信号冲突，均未设计。

组合构建层缺失是 Critical：现在拍板是改文档，M1 之后拍板是改代码+改数据。

## 决策

1. **协同池组合 = 可部署 meta-因子**：协同池输出的每条线性组合视作一个策略候选，与单因子
   走完全相同的路径——注册表查重（FR2.3）→ 统一评测台 → 选择期 → 最终 90 天留出
   （ADR-0003 判据原样适用）→ 部署流水线。**没有任何捷径**：组合不因"来自协同池"而豁免
   任何门禁、成本三档或无前视审计。
2. **因子→策略映射：Top-K 组合取代 Top1-only**：多候选同过留出时，按成本后 Sharpe 取
   前 K 个分别进 dry-run（v0.1：K=3，硬上限 5），其余进 monitoring 队列（防高相关候选
   同窗验证，沿用原 Top1 规则的动机）。K 为配置项，落 `validation/config.yaml`，规则
   先于数据确定。**Top-K 入选判定只允许使用留出窗之前的数据**（数据边界硬约束，见
   架构文档 §4.2）。
3. **权重方案 v0.1 = 逆波动率加权**：组合内各 meta-因子按已实现波动率倒数加权。选择理由：
   参数少、无需估计协方差矩阵；等风险/最小方差等优化类权重明确后移到 v0.2+，不与 v0.1
   里程碑耦合。**逆波动率的估计窗显式限定于留出前数据**——不得在门禁窗上估计权重；若
   实现上估计窗与门禁窗分离，须在 manifest 中声明估计窗位置。
4. **换手预算为门禁输入**：每个再平衡周期设显式换手上限，v0.1 默认单周期换手 ≤100%
   （即全仓翻转一次）。换手预算作为成本模型的门禁输入，接入 ADR-0003 决策 4 的三档成本
   敏感性：超预算的候选在评测台即标记 `over_turnover_budget`，不进留出。
5. **净敞口与同 pair 冲突（v0.1 规则）**：净敞口上限 v0.1 由"每 pair 只允许一个策略持有
   活跃信号"实现；同一 pair 上出现方向冲突的候选信号时，在组合构建层先净额化（netting）
   再写信号缓存——**Freqtrade 只看到净后信号**，永不接收自相矛盾的信号流。进阶净额化
   （跨策略对冲、保证金级合并）明确后移，v0.1 不做。
6. **落位**：组合构建层是因子注册表与信号缓存 writer 之间的独立层：输入 = 通过留出的候选
   集合，输出 = 净后信号缓存条目 + 权重配置。目录与接口归属架构文档，本 ADR 只约束行为。

## 备选方案

- 方案 A（选定）：Top-K meta-因子 + 逆波动率权重 + 换手预算。优点：主引擎产出全有部署
  路径；实现简单、可数参数全部配置化。缺点：逆波动率在因子高相关时分散化有限，需注册表
  查重（FR2.3）兜底。
- 方案 B：维持 Top1-only。优点：零新增组件。缺点：协同池价值全丢弃；同时过留出的候选
  只能串行验证，验证周期×K。
- 方案 C：组合优化器（均值方差/风险平价 + 约束求解）。优点：理论上资本效率最优。缺点：
  v0.1 样本量撑不起协方差估计（正是 D006 指出的功效问题）；复杂度先行违反冒烟闸门精神。

## 后果

- 正面：协同池产出获得完整部署路径，组合 alpha 可被门禁验证而非纸面价值；Top-K 提供
  策略间对照（champion-challenger 的雏形）；同 pair 冲突在进入 Freqtrade 前被结构化消解。
- 负面/义务：K>1 使 dry-run 资源占用×K；组合构建层是新增组件，必须在 M4 前实现且通过
  独立逐 K 线重放审计（无前视三层不变）；净额化逻辑是正确性敏感代码，属检视从严范围。
- 后续行动：K / 换手预算 / 权重方案参数进 `validation/config.yaml`；组合构建层的验收
  标准在对应 feature spec 中定义并引用本 ADR。
